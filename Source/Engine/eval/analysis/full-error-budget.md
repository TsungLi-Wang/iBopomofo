## 1. Executive Summary

**投資委員會的答案：🟡 HOLD 一輪，先花最小成本補上唯一的關鍵盲點，再決定。**

1. **詞庫不是問題（在這份語料上）。** 3,192 個錯字，**LEXICON = 0**。
   每一個金標字都查得到。但 ⚠️ 這**大半是語料建構的假象**：
   `full_reading` 與 `sentence` 逐字對齊，代表讀音是**由金標字查出來的** ——
   詞庫缺口在這份語料裡**結構上不可見**。不得解讀為「詞庫沒問題」。
2. **錯誤只分成兩族，比例是 82:18。**
   `NODE` 2,614（81.9%，正解就在該 walk 節點的候選裡）、
   `PATH/SEG` 578（18.1%，正解字在詞庫、但斷詞把它關在一個選不出它的節點裡）。
3. **最大的一族沒有可投資的介入點。** NODE 81.9% 是最大宗，但它的兩條路都已死：
   方向專屬 expert（⑭-K，system 貢獻 0.082% of D2）、
   通用 expert（⑭-N，條件 AUC 0.459，NO-GO）。
   **「最大」與「最高 ROI」在這裡明確分離。**
4. **NODE 裡有一個從未被當成主線的線索**：75.0% 的 NODE 錯誤，
   引擎選的就是 **unigram 第一名**（1,961 個 = 61.4% of D2）。
   節點重排要對抗的是**詞頻先驗**，而不是「排序器不夠聰明」。
   這把嫌疑人指向 **language model / scoring prior**，不是節點層。
5. **「整句解碼錯」這個名字誤導了兩棒。** 用同樣的操作型定義（目標字以外同句也有錯）
   重算，這批錯裡 **76% 其實是 NODE 家族** —— 正解仍在候選內。
   它描述的是**現象**，不是**成因**。
6. **唯一的關鍵盲點**：我們從來沒有在**全語料**上量過 O1／O3（N-best 路徑層天花板）。
   現有的 97.3%／97.7% 只是六組**目標字**上的數字，`NOT COMPARABLE` 到 D2。
   沒有它，就無法判斷 NODE 的 1,961 個「詞頻先驗」錯誤與 PATH/SEG 的 578 個
   究竟是**重排問題**還是**搜尋問題** —— 而這正好決定要不要動語言模型。

**推薦下一棒**：全語料 oracle ceiling（純分析，見 §12）。
**在它做完之前，不建議啟動任何完整研究週期。**

## 3. Error taxonomy：為什麼只有兩族

題目列了 A–H 八個候選層級。實測資料只支持把它們合併成**兩個互斥族**，理由如下：

| 題目列的層級 | 本棒的處置 | 依據 |
|---|---|---|
| C 候選生成／正解沒進候選 | **合併進 PATH/SEG，且實測為 0** | 每個金標字的單音節讀音都查得到（`bin/lexicon_probe`，1,057/1,057 個 key 都有 unigram）|
| D 斷詞 | **＝ PATH/SEG** | 金標字在 lattice 裡，是斷詞把它關在選不出它的節點內 |
| A 整句解碼／path-level | **不是獨立的一族** | 用操作型定義重算後，76% 落在 NODE（§7）|
| B node-level／候選已有 | **＝ NODE** | 定義相同 |
| F language-model / scoring prior | **是 NODE 的子類，不是平行族** | NODE 中 75.0% 引擎選的就是 unigram 第一名（§5）|
| G context insufficiency | **無法從現有欄位判定** | `UNKNOWN` —— 需要 oracle 才能區分「上下文不足」與「模型偏」|
| E rule / post-processing | **標記但不列入可爭取量** | 本 dump 不含規則層，51 個，`NOT COMPARABLE` |
| H 其他 | **實測 0** | 沒有無法分類的錯字 |

**切開 C 與 D 的方法**（這是本棒新增的唯一測量）：
金標字在該字位的單音節讀音下查得到 → 詞庫有 → 是斷詞／路徑沒走到（PATH/SEG）；
查不到 → 詞庫缺口（LEXICON）。因為 `ReadingGrid` 對每個有 unigram 的跨度都會建節點，
「單音節查得到」＝「lattice 裡存在一個含金標字的單字節點」。

⚠️ **LEXICON = 0 的正確讀法**：語料的 `full_reading` 與 `sentence` 逐字對齊，
說明讀音是**由金標字反查出來的**。所以在這份語料上，
**詞庫缺口在結構上不可能被觀察到**。
這**不是**「詞庫沒問題」的證據，而是「這份語料量不到詞庫問題」。
`NOT OBSERVED IN PRODUCTION TRAFFIC`。

> NODE 家族那 2,614 個「正解在候選裡卻沒被選中」的錯誤，
> 有多少是「正確的整句其實就在 10-best / 200-best 裡、只是排序沒選它」（＝**重排問題**），

這一題的答案直接決定：要投**重排器**還是投**語言模型**。
兩者的工程成本與 regression 風險差一個量級。

## 14. TOP 5 INVESTMENT CANDIDATES

### 1️⃣ 全語料 oracle ceiling（O1 / O2 / O3 over all 74,649 positions）— 🟢 GO

* **為什麼值得**：它本身不改善任何錯誤，但它是後面每一條路線的**分母與方向盤**。
  目前 61.4% of D2 的歸因（「詞頻先驗」）與 18.1%（斷詞）都懸在
  「正確整句在不在搜尋空間裡」這個未量的問題上。
* **現有證據**：六組目標字上 O1 = 97.3%、O3 = 97.7%（`NOT COMPARABLE` 到 D2）。
* **最大可能改善**：0（純分析）。價值在於**避免把一整個研究週期投錯層**。
* **最大風險**：無。不碰 production、不訓練。
* **下一棒最小合法實驗**：見 §16。
* **失敗要不要 DROP**：不適用 —— 這是量測，不是賭注。

### 2️⃣ Language model / scoring prior — 🟡 HOLD

* **為什麼值得**：D2 最大的**有意義**子群：NODE ∧ 引擎選了 unigram 第一名
  = 1,961 個 = **61.4% of D2**。節點層要對抗的是詞頻先驗，
  而詞頻先驗屬於語言模型，不屬於節點重排器。⑭-N 的失敗正好指向這裡：
  節點層看不到的東西，語言模型看得到。
* **現有證據**：只有歸因統計，**沒有任何介入實驗**。`UNKNOWN`。
* **最大可能改善**：`THEORETICAL` 61.4% of D2。實際可達完全未知。
* **最大風險**：**HIGH**。動 `path-char-lstm.bin` 或詞頻會全面影響出貨路徑，
  regression 面極大；`dead-ends.md` 已記錄路線 A（壓平同音詞頻）在真實語料上站不住。
* **下一棒最小合法實驗**：不是現在 —— 先做 1️⃣。
* **失敗要不要 DROP**：不 —— 但要先有 1️⃣ 的數字才知道怎麼設計實驗。
* **為什麼只能 HOLD**：符合「理論 ceiling 很大，但沒有 intervention evidence」→ HOLD。

### 3️⃣ 斷詞／路徑（PATH/SEG）— 🟡 HOLD

* **為什麼值得**：578 個（18.1% of D2），**全部不需要動詞庫**，
  而且 68.0% 落在「該節點只有一個候選」的情形 —— 介入點非常具體：
  那個多字詞不該被選上。這是唯一一條**介入點明確**的路線。
* **現有證據**：本棒首次量到規模與結構。介入效果 `UNKNOWN`。
* **最大可能改善**：`THEORETICAL` 18.1% of D2。
* **最大風險**：LOW–MEDIUM。改斷詞會影響所有句子，但可離線全量驗證。
* **下一棒最小合法實驗**：對這 578 個位置檢查「正確的斷詞在不在 10-best / 200-best」
  —— 純分析，可與 1️⃣ 合併成同一棒。
* **失敗要不要 DROP**：若正確斷詞連 200-best 都進不去 → 這一類要靠搜尋而非重排，
  成本大幅上升，屆時 DROP 或降級。

### 4️⃣ 方向專屬 node expert — 🔴 DROP

* **為什麼不值得**：唯一有 `OBSERVED` 系統級效果的路線，但那個效果是
  **0.082% of D2**（⑭-K）。要換新模型格式、C++/PyTorch parity、長期維護。
  而且每個方向都要自己一輪人工核驗 —— D2 的 NODE 家族有 **1,132 個方向**。
* **證據強度**：HIGH（已完整實測）。
* **符合判準**：「局部效果漂亮，但 system-level denominator 很小」→ 不能 GO。
  加上 ⑭-N 的泛化反證 → DROP。

### 5️⃣ 候選生成／詞庫 — 🟡 HOLD（因為量不到，不是因為沒問題）

* **為什麼不能結案**：本語料上 LEXICON = 0，但那是語料建構的結果（§3 警語）。
  真實使用者會打人名、專有名詞、網路新詞、簡稱 —— 這份 PTT 語料的讀音是
  **由金標字反查**的，結構上不可能出現「詞庫沒有這個字」。
* **證據強度**：**無**（不是弱，是量不到）。
* **下一棒最小合法實驗**：需要一份**讀音不是從金標反查**的語料
  （例如真實注音輸入序列），本棒範圍外。
* `NOT OBSERVED IN PRODUCTION TRAFFIC`。

## 16. 建議的下一棒（設計，本棒不執行）

### 棒⑭-P：全語料 oracle ceiling（純分析）

**唯一問題**：D2 的 3,192 個錯字裡，正確答案在不在引擎的搜尋空間裡？

**最小合法動作**：

1. 沿用⑭-M 的 dump 流程，但對每一句額外輸出 **N-best 路徑（10 條與 200 條）**。
   不改 walk 參數、不改 production、不訓練。
2. 對每一個錯字位標三件事：
   * `in_10best`：金標字在 10-best 的某條路徑的該位置上？
   * `in_200best`：同上，200 條。
   * `in_node`：金標在該 walk 節點的候選裡（＝本棒的 NODE，已有）。
3. 產出全語料版的 O1 / O2 / O3，並與六組目標字版並排
   （明確標 `NOT COMPARABLE`，只作對照）。

**事前 GO / NO-GO（先寫定，看到數字後不得修改）**：

* **若 `in_10best` ≥ 60% of D2** → 大多數錯誤是**重排問題**
  → 下一個完整研究週期投「路徑重排 / 融合分數」。
* **若 `in_10best` < 30% 且 `in_200best` < 45%** → 是**搜尋／語言模型問題**
  → 投語言模型；同時把「重排器」這條線永久關閉。
* **中間** → 依 PATH/SEG 與 NODE 的分佈再切一次，不得直接開訓練棒。

**Stopping rule**：產出三張 oracle 表即停。不訓練、不調 τ、不跑正式 test、不碰 production。

**不得做**：不新增人工標註、不改詞庫、不因為數字漂亮就接著訓練。

## 17. 為什麼 generic Node Expert 被排除（不得改名重開）

⑭-N 的反證是**方法上乾淨的**，本棒不推翻也不重新解釋：

* direction-held-out ＋ document-held-out，leakage audit 七項全綠。
* 總體 AUC 0.758 通過門檻，但事前寫定的 NO-GO 條件
  「held-out direction 大幅崩潰」直接命中（在→再 0.053、教→叫 0.050）。
* 條件 AUC（同一個引擎選字之內，＝出手決策真正面對的比較）**0.459，低於隨機**。

本棒新增的 §10 描述統計**沒有**提供任何新的反面證據：
NODE 家族橫跨 **1,132 個方向**、前 50 個只覆蓋 37.5%、65.9% 的節點候選數 ≥10。
**結論仍是 UNKNOWN，而 UNKNOWN 不構成重開的理由。**

任何以「node-level 池子很大（81.9%）」為由重開此線的提案，
都必須先回答 ⑭-N 已經回答過的那題，且**必須以條件 AUC 為準，不是總體 AUC**。

## 18. Production traffic 限制

**本報告全部證據為 `Corpus-level evidence`，`NOT OBSERVED IN PRODUCTION TRAFFIC`。**

已知的語料偏誤（⑭-M 已量到，本棒沿用）：

* 全部來自 PTT（`ptt-natural` 3,701 句、`ptt-minor` 2,275 句）。
* 語料特有詞彙已進 Top 20 錯誤方向：掛→卦（八卦）、覽→懶（懶人包）、板→版（看版）。
* 正字法／風格變體佔可觸及池的 9.6%（啊/阿、他/她、你/妳、什/甚）。
* **讀音由金標字反查** → 詞庫缺口、注音打錯、選字習慣、造詞、人名、
  專有名詞、簡稱、口語、年齡層差異 —— **全部不可見**。

因此本報告的 ROI 排序只在「PTT 書面語、讀音正確」這個條件下成立。

## 20. 重大 UNKNOWN 清單

1. **正確答案在不在 10-best / 200-best**（全語料）—— 決定投重排還是投語言模型。→ 棒⑭-P
2. PATH/SEG 的 578 個，改斷詞的實際效果與 regression 風險。
3. LM / scoring prior 有沒有任何可操作的介入手段（路線 A 已在真實語料上失敗）。
4. 「上下文不足」與「模型偏」在 D2 上如何區分 —— 需要 oracle。
5. 真實打字流量的錯誤分布、詞庫缺口、讀音錯誤率 —— 完全沒有資料。
6. 正字法／風格變體算不算「錯」—— 產品決定，不是研究問題。
