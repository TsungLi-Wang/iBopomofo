# v2.6.0 — neural rerank wired into the app (candidate A shipped)

First release with a neural sentence reranker in the shipping path. Candidate A
= **v2c int8 + prefix-trie state sharing + Accelerate BLAS**, flag ON, ν=0.75,
N=10. tw538 **387/537 (72%)** vs shipped walk-ON **333 (62%)**, at ~45 ms per
commit, model 9.9 MB.

## What changed

- **Engine** `NeuralLMPathScorer`:
  - int8 loader (`LWLSTM8` magic): per-row symmetric int8 body + f32 scales,
    dequantized to fp32 in RAM at load. Bundle 38.9 MB → **9.9 MB**; load 16 ms;
    RSS +45 MB. (`quantize_lstm_int8.cpp` produces the artifact; loader in
    `NeuralLMPathScorer::load`.)
  - `scoreNBest(paths)` — batched rerank: the 10 candidates' char-id sequences
    form a prefix trie so each distinct prefix computes its LSTM step + full-vocab
    softmax once; matmuls via Accelerate `cblas_sgemv` (forward-declared, not the
    umbrella header — that fails as a C++ module under recent SDKs). Framework
    linked via `OTHER_LDFLAGS` (app) and CMake (`-framework Accelerate`).
  - `reading_grid.cpp` rerank loop calls `scoreNBest` once instead of
    `scoreSentence` per path. Base `PathScorer::scoreNBest` default loops
    `scoreSentence` (back-compat for other scorers).
- **App** `KeyHandler.mm`:
  - **Commit-time gating** (`_rerankThisWalk`): the per-keystroke composing walk
    is **unchanged** (no scorer, ~0.1 ms); rerank runs once at Enter-commit
    (`_handleEnterWithState` re-walks with the scorer, commits the reranked
    buffer). See "Why commit-time" below.
  - Bundled model `path-char-lstm.bin` replaced with v2c int8.
- **Preferences**: `EnableNeuralPathRerank` default **true**; `NeuralPathRerankNu`
  default **0.75**.

## Parallelism acceptance (the gate)

The engine path (`reading_grid`→`scoreNBest`→trie+BLAS, real `NeuralLMPathScorer`)
must equal the eval harness. It does, exactly:

```
$ /tmp/rerank_engine tw538-northstar.tsv data.txt word-bigrams.tsv 0.75 v2c-int8.bin 0.75
NU 0.75 correct 387/537 mean_ms 45.309      # int8, engine path
NU 0.75 correct 387/537 mean_ms 45.7566     # fp32 v2c, engine path (int8 lossless)
```

387/537 @ ~45 ms — identical to the harness Pareto. int8 = fp32 accuracy.

## Trust invariant: hard override survives rerank (32/32)

`override_rerank_check.cpp` — on 32 cases where the rerank moves the answer,
force a hard override (`kOverrideValueWithHighScore`, +42 walk score) at the
diverging node, then rerank:

```
OVERRIDE_TESTED 32 · NBEST_ALL_KEEP_OVERRIDE 31/32 · FINAL_KEEPS_OVERRIDE 32/32
PASS: hard override survives rerank in every tested case
```

The override's +42 dominates the bounded ν·neural term, so a reranked path that
drops the override can never win. User selections are never overturned.

## Why commit-time (not per-keystroke)

The rerank lives in `walk()`, and `_walk` is called per keystroke to update the
inline composing display. Measured per-keystroke walk latency (v2c, N=10):

```
rerank OFF:  mean 0.12 ms   max 0.95 ms     (per keystroke, 6799 steps)
rerank ON :  mean 27.7 ms   max 104 ms      (60-sentence subset)
```

Reranking every keystroke would regress typing latency ~230× — unacceptable.
So rerank is gated to the **commit** walk only: composing stays bit-identical to
the pre-rerank path; the whole sentence is reranked once when it commits.
Consequence to note for dogfood: the inline preview shows the pre-rerank guess
and the committed text shows the reranked (improved) result — the correction
lands the instant you press Enter.

**Follow-ups for the next baton** (not blockers): (1) rerank is gated on the
Enter-commit path only; other commit triggers (punctuation, some space/candidate
commits) still commit the composing buffer without rerank — wire them too for
full consistency. (2) menu label still says "Neural Path Rerank (Experimental)";
rename now that it ships (left as-is here to avoid touching localization).

## Install (dogfood) — step by step

A build is staged at **`~/Desktop/LaoWang-v2.6.0-dogfood/`** (both apps together;
the installer expects `McBopomofo.app` alongside it).

1. Quit any running old McBopomofo/老王注音 first if you want a clean swap
   (System Settings → Keyboard → Input Sources — you can also just install over).
2. Open `~/Desktop/LaoWang-v2.6.0-dogfood/McBopomofoInstaller.app`.
3. Click Install. It kills and restarts the input method automatically.
   - If install stops working after several installs in one session, log out and
     back in (macOS caps IME restarts per login).
4. Switch to 老王注音 and confirm version 2.6.0 (build 2290) in the input menu.

**Rollback switch:** input-method menu → **Neural Path Rerank (Experimental)** →
uncheck. Instantly returns to the old (walk-ON) selection. Re-check to turn back on.
