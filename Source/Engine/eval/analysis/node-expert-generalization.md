# 通用 Node Expert 泛化上界（棒⑭-N · 2026-08-18）

> **本棒不訓練產品模型、不改 τ、不跑正式 test、不增加人工核驗、不造資料、不碰 production。**
> 唯一訓練的是**固定容量的 L2 logistic regression diagnostic**（offline-only），
> 不載入任何 R4／I2 checkpoint，不產生可上線的權重。
> **diagnostic AUC 不是 system net**，本報告任何數字都不得被引用為系統效果。

---

## 1. Executive Summary

**判定：NO-GO。Node Expert 整條研究線 → DROP。**

1. **總體 AUC 過關，但那是 base-rate 假象。** 唯一帶訊號的特徵族是
   `ENG`（引擎側、**字元無關**的數值），held-out 方向＋held-out 文件下 AUC **0.758**，
   5/5 folds ≥ 0.65。字面上滿足事前 GO 門檻。
2. **但事前寫定的 NO-GO 條件「held-out direction 大幅崩潰」直接命中。**
   逐方向看：`在→再` **0.053**、`教→叫` **0.050**、`他→她` **0.150**、
   `掛→卦` **0.177**、`你→妳` 0.435 —— **最大宗的方向全部反向。**
   而且長尾分桶顯示：正例 ≥30 的方向那一桶 AUC **0.405**，
   是**高頻方向最差**，不是低頻崩潰。
3. **原因查明。** 把比較限制在「引擎已經選了 A，這一個 A 是不是錯的」
   （＝出手決策真正面對的比較），ENG 的**條件 AUC 只有 0.459 —— 低於隨機**。
   分數與「該引擎選字的整體錯誤率」相關 0.377，與 label 相關只有 0.247。
   **它在分辨「哪些字容易錯」，不是「這一個是不是錯的」。**
4. **字元身分特徵完全不泛化，而且有害。** `CTX` 上下文字元 0.505（＝隨機）、
   `CAND` 候選身分 **0.319**（顯著低於隨機）。
   把它們加進 ENG 會把 0.758 拉到 0.400。
   這符合預期（未見方向上字元身分權重必為 0），但也證實了
   ⑭-H／⑭-I 量到的表徵訊號**全部是方向專屬的記憶，不是語言規律**。
5. **科學結論：node-level 的可用訊號是 direction-specific 的，不是通用的。**
   要覆蓋 ⑭-M 找到的 775 個方向長尾，就需要 775 個方向專屬專家 —— 不可行。
   而方向專屬那條路已由 ⑭-K 量到系統貢獻 0.082%（佔 D2）。
   **兩條路都關了。**

## 14. 為什麼總體 AUC 是 base-rate 假象：條件 AUC

總體 AUC 問的是「錯的節點能不能排在對的節點前面」——
但那包含了「不同字的錯誤率本來就不同」這個 base rate。
出手決策面對的是：**引擎已經選了 A，這一個 A 是不是錯的？**

| 特徵族 | 總體 AUC | **條件 AUC（同 engine 字內）** | 差 |
|---|---|---|---|
| ENG 引擎側數值（字元無關） | 0.758 | **0.459** | -0.299 |
| CTX 上下文字元 ±6 | 0.505 | **0.479** | -0.026 |
| CAND 候選身分 | 0.319 | **0.162** | -0.157 |
| ENG+CTX | 0.617 | **0.447** | -0.170 |
| ENG+CTX+CAND | 0.403 | **0.211** | -0.191 |

## 15. Baselines 的說明（為什麼沒有 R4 margin）

題目要求三個 baseline。實際可用的只有兩個：

| Baseline | 狀態 | 說明 |
|---|---|---|
| **1. R4 原始 margin** | ❌ **不適用** | 兩個獨立原因：(a) R4／I2 只在 `ㄗㄨㄛˋ` 白名單上訓練，對其餘 970+ 個方向的節點根本無法打分；(b) 它們的訓練**沒有任何 direction hold-out**，拿來當「泛化」baseline 本身就是 leakage。**產出一個有洩漏的數字比沒有數字更糟，所以不做。** |
| 2. ⑭-H 的 A-walk ±6 表徵 | ✅ = 本報告的 `CTX` | AUC **0.505** |
| 3. ⑭-I 的 I2 式表徵 | ✅ = 本報告的 `FULL` | AUC **0.400** |

四個概念本報告嚴格分開，不混用：

* **feature-only diagnostic** — 本棒做的（固定容量 LR，只問訊號在不在）
* **trained diagnostic model** — 同上，仍是 offline-only
* **production I2** — 從未上線，⑭-K HOLD
* **direction-specific expert** — R4／I2 這一類，只對白名單方向

事前寫定（本棒 §13，未修改）：

| 判準 | 門檻 | 實測 | 命中？ |
|---|---|---|---|
| **GO** | 總體 AUC ≥ 0.70 | ENG **0.758** | ✅ |
| | 至少 4/5 folds ≥ 0.65 | 0.74 / 0.78 / 0.72 / 0.87 / 0.72 → **5/5** | ✅ |
| | 單一 direction family 貢獻 ≤ 50% | 最大 `在→再` **4.0%** | ✅ |
| | precision @ 20% override 不低於 baseline | ENG 0.229 vs CTX 0.105 / FULL 0.063 / 隨機 0.106 | ✅ |
| | leakage audit 全綠 | 全綠 | ✅ |
| **NO-GO** | 總體 AUC < 0.60 | 0.758 | ❌ |
| | leakage 無法排除 | 已排除 | ❌ |
| | 結果主要由少數方向支撐 | 否（最大 4.0%）| ❌ |
| | **held-out direction 大幅崩潰** | **`在→再` 0.053、`教→叫` 0.050、`他→她` 0.150、`掛→卦` 0.177；正例 ≥30 那一桶 0.405** | ✅ **命中** |

### 兩條判準同時命中，怎麼裁

事前的 §12 已經預先寫死了裁法：

> 「不要因為 aggregate AUC >= 0.70 就直接 GO。」
> 「特別關注：是不是只有少數高頻方向在撐高 AUC？」

以及 §16：

> 「如果高頻方向很好、低頻方向崩潰，不要稱為通用 Node Expert。」

實測是**比那更糟的一種**：不是低頻崩潰，而是**高頻方向反向**
（正例 ≥30 的桶 AUC 0.405，其中最大的 `在→再` 只有 0.053）。
GO 的整條理由建立在總體 AUC 上，而總體 AUC 已被證明是 base-rate 假象（§14）。

**因此判定 NO-GO。**

門檻沒有被修改，判準沒有被事後調整。
GO 的五個條件確實都達標 —— 但事前同時寫定的 NO-GO 條件「held-out direction 大幅崩潰」
直接命中，而且 §12/§16 的紀律條款已預先指定在這種情形下不得 GO。

## 17. Node Expert 的最終狀態

依事前規則：**NO-GO → Node Expert 整條研究線 DROP。**

| 路線 | 狀態 | 理由 |
|---|---|---|
| **通用 node expert（不設白名單）** | **DROP** | 本棒：跨未見方向不泛化；條件 AUC 0.459 |
| **方向專屬 node expert（白名單）** | **DROP** | ⑭-K：捕獲率 2.4%、系統貢獻 0.082%（佔 D2）；ROI 不足 |
| I2 checkpoint | 保留在分支，**不 merge、不接 app、不 enable production** | ⑭-K HOLD 未動 |

⑭-M 的 REOPEN 到此結束：它問「節點層可觸及的池子是不是比想像大」——
答案是「是」（54.4% of D2）；本棒接著問「那個池子有沒有通用訊號」——
答案是「沒有」。**池子大但撈不起來。**

### 反過來說，本棒也證明了一件正面的事

`作` 0.584、`做` 0.620、`機` 0.793、`板` 0.859、`較` 0.895 ——
**方向專屬的訊號是真的存在的**，⑭-K 量到 I2 的 CI 不含 0 並非雜訊。
問題純粹是：這種訊號**不轉移**。每一個方向都要自己的資料、自己的 dev、自己的模型。
775 個方向 × 每個都要 ⑬～⑭ 這樣一整輪 —— 這是 DROP 的真正理由，
不是「訊號不存在」，而是「訊號不可攤提」。

## 18. 重新開啟的條件（reopen condition）

DROP 不是「證明不可能」。以下任一出現時值得重新評估：

1. 有人提出一個**字元無關但語言學上有意義**的特徵族
   （例如詞性、句法角色、語義框架），並在本棒的同一套 direction-held-out
   切分上把**條件 AUC** 推到 ≥ 0.65。**注意是條件 AUC，不是總體 AUC。**
2. 出現真實打字流量資料，且其錯誤分布與 PTT 語料顯著不同
   （本棒全部證據是 corpus-level evidence）。
3. 有辦法用極低成本自動產生方向專屬的訓練資料與 dev
   （目前每個方向都要一輪人工核驗，這是 775 倍的成本）。

**不設沒有資料支持的 AUC 門檻以外的條件。**

## 19. Limitations

1. **diagnostic 是線性模型。** 固定容量 L2 logistic regression。
   非線性模型可能找到線性模型找不到的訊號 —— 本棒無法排除這個可能。
   但 ⑭-H／⑭-I 用的是同一類模型，結論在同一個尺上可比。
2. **ENG 只有 23 維。** 它是唯一字元無關的一族，設計上就受限。
3. **條件 AUC 是本棒為了解釋現象而算的**，不在事前判準裡。
   它**沒有**被用來推翻 GO —— 推翻 GO 的是事前就寫定的
   「held-out direction 大幅崩潰」。條件 AUC 只是解釋**為什麼**會崩潰。
4. **金標＝語料原文**，六組以外未經人工核驗（⑭-M §13 同一限制）。
5. **全部是 PTT 語料。** 標為 `Corpus-level evidence`，不是 production traffic distribution。
6. **965 / 988 個錯誤方向 n < 10**，標 INSUFFICIENT POWER，只進 aggregate。
   逐方向結論只對 23 個可評估方向成立。
7. **本棒沒有做 calibration、operating point、net gain** —— 依規定 GO 才做，本棒 NO-GO。
