## 3. `做→坐` 完整診斷：不是覆蓋問題，是能力問題

| | audited dev | Natural test |

| 模型 argmax 選了 | 做 16、坐 2 | **做 65**、作 5、坐 3 |
| 跨度 | 單字 14、2字 3、3字 1 | 單字 57、2字 16 |

**margin 四分位全是 0.00，代表模型的 argmax 就是引擎已經選的「做」。**
它不是「有把握但被 τ 擋住」，而是**根本不認為該改**。候選裡有「坐」（99%），
它就是不選。

→ 這一格 **dev 與 test 完全一致**（都是 2 次出手、都以「做」為 argmax）。
**dev 忠實地報告了這個失敗模式，是我在棒⑭-B 沒有把它當一回事。**

（同樣情形：`做→作` dev 出手 1、test 出手 0；`做→座` dev 1、test 0。
凡是引擎選「做」的錯，模型一律不動。）

## 4. 真正的漏洞：`作→作` 的單字節點子群

dev 與 test 在**方向**上一致，但在**結構**上不一致：

| 格 | dev n | dev 單字佔比 | test n | test 單字佔比 |
|---|---|---|---|---|
| **作→作** | 30 | **6.7%（2 個）** | 160 | **33.1%（53 個）** |
| 做→做 | 33 | 51.5% | 425 | 57.9% |
| 坐→坐 | 30 | 33.3% | 48 | 45.8% |
| 座→座 | 31 | 22.6% | 67 | 25.4% |

而傷害幾乎只發生在單字節點：

| 引擎本來就對的節點 | n | 改壞 | 傷害率 [Wilson 95%] |
|---|---|---|---|
| **Natural test · 單字** | 338 | **34** | **10.06% [7.29, 13.73]** |
| Natural test · 多字詞 | 362 | 3 | 0.83% [0.28, 2.41] |
| **audited dev · 單字** | **36** | **0** | 0.00% [0.00, **9.64**] |
| audited dev · 多字詞 | 88 | 0 | 0.00% [0.00, 4.18] |

**37 次改壞裡有 34 次（92%）在單字節點。**

**dev 在這個子群只有 36 個節點，觀察到 0 次改壞，Wilson 上界 9.64% ——
剛好落在真值 10.06% 的下方。** 也就是說：這份 dev **在數學上就不可能**
偵測到這個傷害率。原因有兩層：

1. **抽樣組成**：我在棒⑭-A-1 是「每個 engine==gold 格抽 30 筆」，且從**訓練語料母體**
   均勻抽。訓練母體的 `作→作` 有 86% 是「工作／合作／作為」這類複合詞，
   所以 30 筆裡只有 2 筆是單字。測試集是為消歧而建的，單字佔 33%。
2. **運氣**：36 個單字節點在 10% 傷害率下觀察到 0 次的機率約 2.2%。偏低，但沒有低到不可能。

| 來源 | 引擎本來就對的節點 | 改壞 | 傷害率 | **Wilson 95% CI** |

**事前就該判定證據不足、不進正式測試**。

## 7. Context filtering（句長 ≥9）到底改變了什麼分布

| | 不過濾（R1a） | 句長≥9（R4） |
|---|---|---|
| 全域筆數 | 161,478 | 100,410（−37.8%）|
| hard 佔比 | 18.7% | 18.1% |
| 單字佔比 | 64.5% | 62.4% |
| 作做坐座 筆數 | 3,156 | 2,075 |
| 作做坐座 單字佔比 | 22.3% | 21.1% |

被移除的 61,068 筆：hard 19.6%、單字 68.1% —— 跟母體（18.7% / 64.5%）**幾乎一樣**。

逐方向的比例也幾乎不變（作→作 50.3%→49.5%、做→坐 1.5%→1.6%，各格保留率 64–81%）。

**結論：context filtering 沒有造成任何有意義的分布偏移。**
它就是均勻地丟掉 38% 的資料。所以 R4 相對 R1a 的
precision 0.421→0.481 **不能歸因於分布改變**；最一致的解釋是移除了
「連人都判不出來」的短片段雜訊，但**效果量小、dev 又欠功率，這條目前算未證實**。
依指示，本棒不採用它、也不因此改訓練。

## 9. 下一版 audited dev 規格（只提設計，不執行）

1. **doc_id 完全隔離**：沿用現行做法（訓練整份排除 audited 文件）。
2. **分層維度要加第三軸**：engine choice × 方向 × **節點跨度（單字／多字詞）**。
   `作→作·單字`、`做→做·單字`、`坐→坐·單字`、`座→座·單字` 每格至少 **120 筆**
   —— 這樣 0 次改壞的 Wilson 上界才會 ≤3%，能分辨「真的無害」與「10% 傷害」。
3. **規模按「模型會出手的引擎正確節點數」算，不是按總題數**。
   以 R4 在單字節點約 10% 的出手率回推，四個對角線單字格共 480 筆，
   加上錯誤方向的覆蓋，**整份約 900–1,100 筆**（現在 263）。
4. **對測試中真正重要的失敗模式過抽**：`做→坐`（Natural 最大宗，73/186 個錯）、
   `作→座`、`作→做`。但 —— 
5. **稀有方向不得憑空製造**：`坐→作`、`坐→座`、`座→作`、`座→坐` 在 Natural 母體是 0，
   在訓練母體是個位數。有多少抽多少，不足就標「無法評估」，不要補。
6. **報 aggregate 一律逆機率加權**（inverse-probability weighting），
   且**同時報未加權與加權兩種**。
7. **每一格都要報 Wilson 區間**；「0 次改壞」一律寫成區間上界，不准寫成 0%。
8. **凍結規則改成「預估淨值的 95% 下界 > 0」**才准進正式判準。
9. `做→坐` 不得再出現 0 coverage —— 但要注意本棒的發現：
   它**不是**沒被覆蓋，而是模型在那裡一律不動。dev 要能把「模型不出手」
   本身當成一個要報告的失敗模式，而不是只看救／壞。
10. 核驗介面沿用現有三件套（遮字、可中斷續做、正確性由工具自動算）。
