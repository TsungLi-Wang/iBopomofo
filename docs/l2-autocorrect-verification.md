## 前置

1. 已安裝並啟用本次 build 的i注音（Info.plist 1.8.x）。
2. 本機 AI 模型已就緒：`pgrep -lf llama-server` 有結果（本機目前有）。
3. 開啟實驗開關：**輸入法選單 ▸「AI 句末自動校正（實驗）」打勾**（等同 `Preferences.enableAIAutoCorrection = true`）。

## 觸發條件（來自 `AIAutoCorrector.isCorrectableSentence`）

同時滿足：

- 游標在句尾（`cursorIndex == composingBuffer.count`）。
- 組字區長度 ≥ 4（`minComposingLength`）。
- 且下列任一：
  - 以句末標點結束：`。！？!?…`（逗號、頓號**不算**）；或
  - 長度 ≥ 8 且含歧義字（`在再的得地做作知資麼摸裡裏哪那这這` 等）。
- 觸發後有 **0.8s debounce**；繼續打字會取消這次請求。

## 驗證步驟與預期

| # | 操作 | 預期 |
|---|------|------|
| 1 | 打一句含同音錯字並以句號結束，例：`我資道了。` | 停頓約 1 秒後，游標旁跳**低調提示**「建議 我知道了。（Tab）」。組字區文字**不變**（非破壞性）。 |
| 2 | 承上，按 **Tab** | 提示消失，送出**修正後**整句「我知道了。」。 |
| 3 | 重打步驟 1，這次**不要按 Tab、繼續打字** | 提示自然消失，原文照舊，繼續打的字接在後面（AI 沒有偷改）。 |
| 4 | 打一句 AI 認為已正確的：`今天天氣很好。` | **不跳提示**（`suggestionOutcome == .noHint`），不打擾。 |
| 5 | 打長句不加標點但含歧義字（≥8 字），例：`我在想這件事情在不在` | 可能跳提示（長句歧義路徑）。跳了則同步驟 1 行為。 |
| 6 | 打短句 `好嗎？`（<4 字） | **不觸發**（低於長度門檻）。 |
| 7 | 打逗號句中停頓 `我在家，準備` | **不觸發**（句中標點不算句末）。 |
| 8 | 提示出現時把游標移回句中再打字 | 提示應消失、不誤套用（游標不在句尾 → 不重觸發；buffer 變更 → 舊結果丟棄）。 |

## 本次改動的驗證重點（低調提示）

- 提示文字應為新的低調版 **「建議 …（Tab）」**（en：`Suggest: … (Tab)`），不再是舊的「AI 建議：…（Tab）」冗長版。
- 提示內容現在掛在 `InputState.Inputting.aiTooltipMessage`（顯示真相來源）＋ `pendingAISuggestion`（採用真相來源由 Coordinator 持有）；兩者一致。
- 下一個按鍵重繪 Inputting 時 tooltip 會自然收掉（`handle(Inputting)` 開頭 `hideTooltip()`）。

## 若不如預期，先看這裡

- **完全不跳提示**：確認開關有打勾、模型有就緒（`llama-server` 在跑）、句子有達門檻且游標在句尾。
- **提示跳了但 Tab 沒反應**：確認 Tab 沒被其他候選／關聯詞路徑先吃掉（`InputMethodController.swift:340` keyCode 48 的串接順序：候選視窗建議 → 候選建議 → 自動校正建議）。
- **送出後文字被引擎蓋回原文**：這是讀音驅動引擎的假修正症狀——代表有人又用 `setMarkedText` 塞字。正解走 `docs/engine-node-override.md`。
- **診斷本機執行期**：短期可加固定檔 log 定位，查完務必移除；**不要**用 `log stream` 撈 iBopomofo（噪音爆量）。
