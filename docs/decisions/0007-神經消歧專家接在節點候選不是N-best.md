# 0007 — 神經消歧專家要接在「節點的候選清單」上，不是 N-best 路徑

**決定**：如果將來要做神經消歧專家（對話裡叫過「中文警察」），它**只能**接在
節點的候選清單上，掛點沿用 `ParticleRuleDisambiguator` 現在用的
`selectOverrideUnigram`。**這一篇只定接線位置，不開做。**

四條約束，缺一不可：

1. **掛在節點層**：走完 walk 之後，在節點**既有**候選裡改選。不重跑模型、不發明新字。
2. **棄權＝不 override**：沒把握就什麼都不做，讓引擎維持原判。
   沒有棄權的專家會把「不確定」變成「亂改」，那正是六組同音規則翻車的樣態。
3. **使用者手選永不被蓋**：`node->isOverridden() && !isAppliedByUs(node)` → 跳過。
   這條已經有測試釘住（`RescoreWalkNeverOverridesUserChoice`），新機制要沿用同一道防護。
4. **路徑層的 v2d 只對「在／再」證實過，不得默認同一帖藥能套到別組**：
   作做坐座 已實測 NO-GO（見 [`docs/dead-ends.md`](../dead-ends.md) C 節）。
   每一組要各自證明，用真實語料、逐題配對。

## 為什麼是節點層

因為兩層的天花板差很多，而且方向是固定的（見
[`0004`](0004-天花板與錯誤分層.md) 的 oracle 表）：

```
路徑層（v2c 對 N-best 重排）   85.3%
節點層（在既定斷詞下改選候選）  95.9%
```

最極端的是「的／得」：路徑層天花板 **62.1%**，而規則層已經把它推到 63.3% ——
**比天花板還高**。正解那條路徑連前兩百名都擠不進去，所以路徑重排器再強也**看不到**
正確答案。這解釋了為什麼路線 A（路徑融合）對這組只賺 1 題，而文法規則（節點內改選）
賺 21 題。作做坐座 是同一個模式（O1 71.1% vs O2 98.3%）。

接線位置選錯不是「效果差一點」，是**上限直接被架構鎖死**。

這也是 [`0001`](0001-同音消歧不是語言生成.md) 的直接推論：問題是判別不是生成，
候選集合是封閉的（讀音決定），所以該做的是在封閉集合裡選對，不是重新產生語言。

## 這一層不負責什麼

**整句解碼錯不是這層的題。** EX1166 封存集剩下的 510 個錯裡，220 個（43.1%）是
整句被解碎、目標字只是被連坐（「先寄的初稿」→「先記得初稿」）。
節點內改選碰不到這類錯，加再強的節點層專家也修不到。

所以 0007 **不開做**：先知道接哪裡，不代表現在該接。真要動手之前得先回答
「這個機制要修的是哪一層的錯、那一層還有多少題在桌上」——
而那張地圖在真實語料上長什麼樣，目前只有 EX1166 版本
（見 `Source/Engine/eval/analysis/real-corpus-error-layers.md`）。

## 什麼會推翻它

證據顯示瓶頸回到「候選沒進來」或「整句解碼錯」，而不是「節點內選錯」——
那時候該投的是候選生成／斷詞／整句解碼，不是節點層排序器，這篇的前提就不成立了。
（目前的量測指向相反方向：候選死角只有 1.2%，節點層 oracle 95.9%。）
