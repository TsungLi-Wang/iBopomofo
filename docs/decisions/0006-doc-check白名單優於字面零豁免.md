# 0006 — doc-check 的家目錄路徑：維持四項白名單，不做「字面版／零家目錄豁免」

**決定**（Johnny 2026-08-13 裁定）：`doc_check.py` 的 `MAINTAINER_LOCAL_ROOTS`
維持四項白名單。**不**追求「文件裡一個家目錄路徑都不出現」的字面版。

具體禁止兩件事：

- 改 `MAINTAINER_LOCAL_ROOTS`（要加第五項得改程式並在旁邊寫下理由）
- 把 `CLAUDE.md` / `AGENTS.md` / `AI_HANDOFF_PROMPT.md` / `README.md` 裡的
  `` `~/…` `` 改寫成不帶反引號的散文

## 為什麼

- 四個東西**依法／依隱私一定住家目錄**（`~/Library/` 是 macOS 規定的位置、
  `~/Documents/i注音-語料/` 是不可上傳的私有語料、`~/laowang-data/` 是大資產、
  `~/.claude/` 不屬於本 repo）。文件必須把它們寫成**可複製的路徑**，
  而且本機仍然做存在性檢查。
- **字面版只是拿掉反引號讓檢查器看不見。** 例外沒有消失，它變成散文。
- **必讀檢查也靠反引號。** 改成散文之後，「必讀：本機 Documents 裡的某某檔」
  會直接漏接 —— 那比白名單**更弱**，不是更嚴。
- 規則要單純：**路徑就寫成路徑**；repo 外允許的根只有一份名單，
  加第五項得改程式並寫理由。

## 什麼會推翻它

白名單長到需要「分類」才說得清（例如超過十項、或出現「這台機器才有」的條目）——
那表示 repo 又開始依賴 repo 外的東西，該回頭處理的是那個依賴本身，不是這條規則。
