# 0003 — 現成語料榨乾了，下一段燃料是真人的手動校正

**決定**：產品的核心迴路是「使用者手動改對一個同音錯字 → 那一筆被收集 → 模型變準 →
一個人的努力貢獻給所有人」。**手動改字＝獎勵訊號**，這是 Johnny 定的永久產品目標第三段。

## 為什麼

現成語料能榨的判別知識已經榨乾了 —— 而且語料本身還會**教錯**：
PTT 語料在「的／得」程度副詞上只有 39.5% 寫對，拿它訓練會很努力地學會寫錯。

真人校正是唯一還沒用、而且真正新的燃料，因為它有三個現成語料沒有的性質：

1. **依定義就正確**（人是為了打對才去改的）；
2. **依定義就是難題分布**（模型選對的位置不會被改）；
3. **持續產生**，不會像固定語料一樣被榨乾。

這一點被 2026-08-10 的實測背書：對比訓練時，**3,262 題的難題資料贏過 15.5 萬句隨機語料
47 倍的資料量**。決定成敗的是分布，不是量。校正事件正好就是那個分布。

## 三段結構（同一條資料迴路的不同段）

| 段 | 是什麼 | 狀態 |
|---|---|---|
| 本機學習 | 校正寫回 UOM soft，同前文重打就記得 | 已上線（v2.14.0） |
| 乾淨記錄 | `manual-correction.log` schema v1，含 `wrong_char` ＋ 前文 | 已上線 |
| 群眾層 | 把大家的校正彙總成共享表（區塊鏈那條的核心） | 未做 |

**新北極星、校正迴路、群眾／上鏈，本質是同一條迴路的不同段。** 心裡要一直有這張大圖。

## 為什麼一定要有群眾層

本機學習很**專一** —— 只在該特定前文生效（UOM 的 key ＝ 前詞＋讀音＋詞）。
對單一使用者的幫助有限。**廣度只能靠群眾層**：把很多人的校正彙總，才會變成能改善
預設行為的知識。

## 隱私是這條路的硬約束，不是附註

`user-override-cache.dat`、`manual-correction.log`、`rerank-diff.log` 全部**只在本機**，
永不進 git、永不上傳、永不附在當機報告裡。要往群眾層走，第一個要設計的不是演算法，
是**隱私與 opt-in**（打字內容是最敏感的資料之一）。這件事沒設計好之前不要動手收資料。

## 什麼會推翻它

如果真的收到校正資料之後，發現它的量太小或雜訊太大（使用者常常改錯、或改的是風格而非對錯），
那這條燃料就不成立。**要先收一小批真實校正做量測，再談群眾層架構** ——
不要反過來先蓋架構。
